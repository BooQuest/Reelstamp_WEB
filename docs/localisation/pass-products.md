# 이용권 상품 한국어·영어 표시

상품명·설명은 Backend의 `subscription_plan_translations`에서 관리합니다. WEB은 상품 코드별 이름을 하드코딩하거나 DB 원문을 UI 번역 함수로 재번역하지 않습니다.

## 적용 화면

요금제, 구매 확인, 결제 결과, 구매한 보유 이용권, 구매 결제 내역에 적용합니다. 쿠폰 고유명·혜택, 기존 구독 상품과 외부 결제창은 변경하지 않습니다. 화면에 없던 설명 영역도 추가하지 않습니다.

상품 조회·서버 렌더링은 현재 쿠키 언어를 전달합니다. 상품 응답의 언어와 현재 UI 언어가 다르면 이전 이름 대신 로딩 안내를 표시합니다. 구매 버튼은 새 언어의 상품을 받기 전까지 비활성화합니다. 결제 결과 조회는 언어별 요청을 취소·교체하며 늦은 이전 응답은 반영하지 않습니다.

기간은 `durationLabel(product, locale)`에서 단수·복수를 처리합니다. 가격·원화·할인율·시간대·판매 설정은 그대로입니다. 구매 입력과 결제 중복 방지 키에는 locale을 넣지 않습니다. 구매 요청의 locale은 요청을 보낼 때 고정되며 언어 변경 자체가 주문을 생성하지 않습니다.

## DB와 배포

SQL은 Backend의 `reelstamp-api/docs/localisation/passes/`에 있습니다. 사용자가 01-preflight → 02-migrate → 03-verify 순서로 적용한 뒤 Backend → WEB 순서로 배포합니다. 기존 템플릿 SQL은 다시 적용하지 않습니다. DB 적용 전 새 Backend를 서비스에 연결하면 번역 조회가 실패하므로 먼저 SQL을 적용해야 합니다.

실제 영어 표시명은 API의 `displayProductName`을 사용하고 `displayLocale`로 이전 응답을 구분합니다. `productName`은 구매 당시 기록이며 외부 결제 전달에도 사용하므로 덮어쓰지 않습니다. 영어 번역이 없는 기존 내역은 삭제하지 않고 Backend가 구매 당시 기간으로 만든 일반 이름을 표시합니다.

## 검증 기록

- WEB 전체 테스트: 68개 파일, 488개 테스트 통과.
- WEB 타입 검사·프로덕션 빌드 통과. 실행 중인 개발 서버와 겹치지 않도록 `.next/pass-localisation-build`에 빌드했습니다. Next가 추가한 임시 tsconfig 설정은 복원했습니다.
- 전체 ESLint는 기존 오류 10개·경고 17개이며, 수정한 파일에서는 오류·경고가 없습니다. 기존 문제는 HEAD 소스와 비교했습니다.
- Backend: 30개 클래스, 187개 테스트 통과, 실패·스킵 0. 외부 서비스 설정이 필요한 `ReelstampApiApplicationTests` 1개는 기존과 같이 임시 Gradle 설정으로 제외했습니다.
- 새로 생성한 `127.0.0.1:55439/reelstamp_localisation_test` 테스트 DB에서 마이그레이션과 주문·권한 회귀 테스트를 수행했습니다. 각 테스트의 임시 스키마와 테스트 DB 프로세스를 정리했습니다.
- 별도 테스트 상품 API와 WEB으로 1440px·390px·320px 요금제 화면을 확인했습니다. 영어 상품명·기간 단복수·가로 넘침, 한국어 복귀·새로고침을 검증했습니다. 실제 로그인·결제 화면 전체를 서비스 환경에서 검증한 것은 아닙니다.
- 구매 확인 입력·진행 중 요청·실패 후 재시도 키 보존, 결제 결과의 늦은 이전 언어 응답 무시, 영어 강제 구매 차단, PG 원본 상품명 유지, 읽기 API의 민감 필드 제외는 자동 테스트로 확인했습니다.
- 실제 PG 결제·환불 호출과 서비스 DB SQL 실행은 하지 않았습니다. 개발 DB 적용 후 실제 로그인 상태의 화면 확인은 남아 있습니다.
